# RFC 索引與建立方式

[English](README.en.md) · [內部文件](../README.zh-TW.md)

## 議題索引

目前尚未建立 RFC；不預先填入決策或虛構核准紀錄。新增時記錄 RFC ID、主題、文件狀態、決策狀態與雙語連結。

## 何時建立

有重要設計選擇、需要比較方案或影響多份文件時建立 RFC。一般缺漏先記錄於相關文件的待釐清事項。

## 命名與必要章節

- 檔名：`0001-<topic>.zh-TW.md` 與 `0001-<topic>.en.md`，後續依序編號。
- Metadata 沿用[文件流程](../../governance/authoring-workflow.zh-TW.md)，兩版共用 RFC ID。
- 章節：背景與待決問題、目標／非目標、約束、方案、比較與取捨、建議、驗證需求、決策與理由、相依文件、待釐清事項、參考資料。
- 方案須有適用證據；建議不是已核准決策。決策由使用者確認後記錄審閱者、已知日期與理由。

## 待釐清事項

後續依實際設計問題決定是否開 RFC。例如 Doris 版本選擇仍待定，但尚未決定是否需要獨立 RFC。
